# Configuration relevant to the comparison (secrets removed)
- Service: Render web service btc-pin-radar, Node runtime, build `npm install`, start `node pinradar_server.js`, one instance, auto-deploy on commit to main of didubin-code/btc-ai-backend. Deployed commit 3125bbc0 (I2). The page is served by GitHub Pages from main of didubin-code/Btc-signal (btc_pin_radar.html = H1.1).
- The candidate reads one new variable, PR11_MODE (off | shadow | gate; unset = gate). The release plan deploys it unset. No other configuration change is part of the candidate.
- Every other tunable is an in-code default overridable by environment variable; the comparison used the defaults in the source files (for example SETTLE_WINDOW_SEC 60, BRTI_STALE_MS 2500, BRTI_COUNT_TOL 2, MIN_TRADE_ASK_CENTS 90, PRED_LOG_MAX 5000). The complete list of variable NAMES read by the server (values deliberately not included; three of them, KALSHI_KEY_ID, KALSHI_PRIVATE_KEY and OPENAI_API_KEY, are credentials): see `grep -o "process\.env\.[A-Z0-9_]*" sources/*.js | sort -u`. Whether production overrides any default is not recorded in this package; the exact replay reproduces the served states with the defaults, which is the evidence that none affecting the decision path is overridden.
- Fee model: the server's default (FEE28, Kalshi quadratic taker fee, ceil(0.07 × C × P × (1 − P)) per order); Kalshi's series record for KXBTC15M says fee_type quadratic, fee_multiplier 1 (outputs/baseline/kalshi_series_KXBTC15M.json).
