## 2. PROVEN LOCKED — exact condition, documentation correction, assumptions, bypass
Exact code (live I2 and the candidate are byte-identical on these lines): `lockGeometry25`, live line 1641: `provenUp = nLock > 0 && lobs > 0 && ((1 − PROVEN_MARGIN_FRAC) × lsum) / W ≥ strike`, with PROVEN_MARGIN_FRAC = 0.0025, W = 60, `lsum` = the sum of the engine's own 1-Hz composite index samples matched to each passed print second (nearest sample within ±600 ms; a print less than 1.1 s old with no sample yet takes the live index), `lobs` = the number of such samples (a missing one contributes nothing, which is conservative). `m25Decide`, line 1477: the state is PROVEN LOCKED only if `provenSide === side` (provenSide is 'UP' or null: NO is never proven) and the official-reference gate list is empty (`brtiGate27`: official/proxy divergence above $40, or official-reference flip risk above 5 %, withholds it — v2.8 fix D4). The same formula exists in the 2.4 geometry (`provenYes`, line 1258) used by the legacy tier function.
Correction: this is a documentation correction, not a code change. The audit's sentence "the recorded prints alone already exceed 60 × strike — the exact certainty condition" was wrong: the sum is of the engine's composite samples at the passed print seconds, not of the official BRTI prints. FEASIBILITY.md's description ("a stress rule on the recorded prints with a 0.25 % price margin, not the exact certainty condition") was the accurate one and stands.
Official-print identity, completeness, confirmation, rounding, revisions: the server receives the official accumulator (Kalshi's `last_60s_windowed_average_15min`: count and running average) and uses it for the settlement panel and the official gates, not for PROVEN; it does not receive the individual official prints. Measured on 39,978 live LOCKED/PROVEN rows with an official reference: |official − proxy| median 0.41 bps, p90 1.08, p99 2.20, max 6.26 bps; the margin is 25 bps at $64k; the divergence gate is $40 ≈ 6 bps. Rounding of the settlement average to the strike's precision cannot convert a margin of 0.25 % into a reversal. Revisions by CF Benchmarks or Kalshi after the fact are not detectable by the server (the existing note "still subject to CF Benchmarks data" stays).
Assumptions required for the mathematical conclusion: (A1) each official print for a passed second is at least 0.9975 times the engine's sample for that second; (A2) no later revision of the prints or the settlement; (A3) the settlement is the simple average of the 60 prints with ties YES; (A4) when the official feed is down (reference PROXY) the official gate cannot fire, so A1 is then unverified by the server. Losing-side bypass: PROVEN LOCKED exists only for YES; a losing YES PROVEN would require the official prints of the passed seconds to average more than 0.25 % below the engine's samples (about four times the largest divergence in 40,000 live rows and six times the gate limit) or a revision. Observed: one PROVEN LOCKED row in 113,465 live rows (won); none in any sample tape. PR11 never relabels or withholds PROVEN LOCKED (self-tested; it cannot occur beyond 120 s because it needs passed prints).
